# 个性化陪读阅读室｜V0 验证任务书

## 1. 本阶段只验证一个问题

> 一位正在学习机器学习的中文用户，能否在陪读流程的帮助下，读完一篇论文或项目 README 的一个核心章节，完成答题与复述，并准确说出自己原来误解了什么？

V0 不验证“功能是否丰富”，也不验证“角色是否足够好看”。它只验证用户是否真的完成了一次学习闭环。

## 2. 第一批目标用户

- 正在学习机器学习、深度学习或 Python 项目开发；
- 有阅读论文、GitHub README 或技术文档的实际需要；
- 不是完全零基础，但经常读到一半失去耐心；
- 使用过通用 AI，却仍然无法确认自己是否真正理解。

暂不服务所有专业、所有年龄和所有材料类型。

## 3. V0 的完整流程

```text
上传一份 PDF 或 Markdown
→ 生成材料地图
→ 用户选择一个核心章节
→ 查看严格解释
→ 查看陪读人格解释
→ 完成三道理解题
→ 用自己的话复述 3—5 句
→ 系统指出遗漏、混淆和错误
→ 每条诊断跳回对应原文
→ 保存阅读档案
```

## 4. V0 必须有的功能

1. 支持一份可复制文本的 PDF 或 Markdown。
2. 材料地图包含：问题、方法、实验、结论、局限。
3. 每段讲解分为严格轨和陪读轨。
4. 严格轨中的关键结论可以定位到原文页码、章节或段落。
5. 用户提交答案前不能看到标准答案。
6. 提供三道理解题。
7. 要求用户进行一次 3—5 句复述。
8. 诊断区分：遗漏、概念混淆、事实错误、表述不清。
9. 保存本次阅读材料、答案、复述和错因。

## 5. 本阶段明确不做

- 真人音色克隆和 RVC；
- 角色市场、社区和多人互动；
- 复杂立绘、动画和游戏地图；
- 自动抓取全网内容；
- 扫描版 PDF 和任意复杂排版；
- 一键生成整篇作业；
- 黄风档案馆、天机世界的系统级联动；
- 为了展示技术而搭建复杂的多代理系统。

## 6. 第一轮成功标准

第一轮找 5 位真实目标用户，每人至少完成一份材料的一个章节。

继续开发的最低信号：

- 至少 3 人完成三道理解题；
- 至少 2 人完成复述；
- 至少 2 人能明确说出系统发现了自己的哪个误解；
- 至少 2 人愿意在一周内使用第二份材料；
- 关键讲解与诊断的原文引用经人工检查基本准确；
- 产品负责人和开发者自己愿意持续使用。

如果用户只觉得角色有趣，却不愿答题、复述或再次使用，说明核心闭环尚未成立。

## 7. 开发前的第一项实验

先不用开发完整网站，手工制作第一份“陪读学习包”：

1. 选择一篇自己熟悉、能够判断对错的机器学习论文或 README；
2. 选择其中一个核心章节；
3. 定义用户学完后必须能回答的三个问题；
4. 按原文制作严格解释；
5. 将严格解释转换为陪读人格表达；
6. 制作三道题及其评分依据；
7. 准备正确、部分正确和错误的复述样例；
8. 找一位用户完整走一次流程并记录卡点。

## 8. 第一周行动表

### 第 1 天

- 确定第一篇材料；
- 确定核心章节；
- 写出三个学习目标；
- 标记支撑每个学习目标的原文位置。

### 第 2—3 天

- 制作材料地图；
- 制作严格解释和陪读解释；
- 制作三道理解题、答案和评分规则；
- 制作复述诊断规则。

### 第 4—5 天

- 找 2 位目标用户完成流程；
- 记录中途退出、看不懂、引用不准和诊断不服气的位置；
- 修改学习流程。

### 第 6—7 天

- 再测试 3 位用户；
- 统计答题、复述和第二份材料意愿；
- 决定进入网页原型、继续修改，还是停止当前方向。

## 9. 进入开发阶段的门槛

只有在手工实验中出现下面的证据，才开始制作正式网页：

> 用户不仅认为讲解“挺有意思”，还实际完成了答题和复述，并愿意继续读第二份材料。

## 10. 当前实验材料

首篇材料已确定为：

> Jie Hu, Li Shen, Gang Sun. *Squeeze-and-Excitation Networks*. CVPR 2018.

第一轮不要求用户一次读完整篇论文，先验证第 3 节 “Squeeze-and-Excitation Blocks”：

- SE 模块解决什么问题；
- Squeeze 和 Excitation 分别做什么；
- SE 模块如何接入 ResNet；
- 用户能否把论文公式对应到张量形状和代码操作。
