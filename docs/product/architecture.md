# 个性化陪读阅读室｜v.0 产品架构

## 架构目标

v.0 必须跑通一条真实前后端链路，同时为后续任意 PDF、用户系统和应用上架保留扩展位置。

```text
React Web
  ↓ REST / JSON
FastAPI
  ├─ 材料服务
  ├─ 学习会话服务
  ├─ 规则评分
  ├─ OpenAI 学习引擎
  └─ SQLite 数据存储
```

## 前端职责

- 展示材料与材料地图；
- 展示严格轨和陪读轨；
- 收集题目答案与用户复述；
- 展示诊断、原文位置和阅读档案；
- 上传 PDF/Markdown；
- 管理加载、失败、空状态和流程进度；
- 不持有模型密钥，不直接调用模型。

## 后端职责

- 管理公开材料数据和隐藏评分规则；
- 创建并保存学习会话；
- 接收答案和复述；
- 对内置 SENet 使用可重复的规则评分；
- 对用户材料使用 OpenAI Responses API 生成学习包和诊断；
- 保存完成结果并提供阅读档案；
- 校验文件类型、大小与页数。

## 数据边界

学习者可见：

- 材料地图；
- 严格轨；
- 陪读轨；
- 题目；
- 提交后的评分、诊断和原文位置。

学习者提交前不可见：

- 标准答案；
- 评分规则；
- 错因匹配词；
- 内部提示词。

## 核心 API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 服务健康状态 |
| GET | `/api/personas` | 陪读人格列表 |
| GET | `/api/materials` | 材料列表 |
| GET | `/api/materials/{id}` | 材料详情 |
| POST | `/api/materials/upload` | 上传并生成学习包 |
| POST | `/api/sessions` | 创建学习会话 |
| GET | `/api/sessions/{id}` | 获取会话 |
| POST | `/api/sessions/{id}/evaluate` | 提交答案与复述 |
| GET | `/api/archive` | 阅读档案 |

## v.0 存储

SQLite 保存材料和学习会话。材料的公开数据与隐藏评分规则分开保存。v.1 可迁移至 PostgreSQL，而不改变客户端 API。

## AI 调用

- 默认模型通过 `OPENAI_MODEL` 配置；
- 使用 Responses API；
- 输入包含带页码的文本、学习目标和严格 JSON 输出约束；
- API 密钥只由后端从环境变量读取；
- 内置 SENet 即使模型不可用也能完整运行；
- 用户上传材料若模型失败，返回明确错误，不生成伪造学习包。
